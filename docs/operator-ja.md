# 運用コンソール — 操作の手引き

給与アクター `cloud-itonami-isco-4313` の運用者向け。日本語の画面と、
それが**何を主張していないか**の説明です。

> **この system は法定様式の書類を出しません。** 給与支払明細書も賃金台帳も、
> 記載事項を定める法令をこの repository は読んでいないので、様式が要件を
> 満たすかどうかは未検査です。金額の多くも当 repository が計算したものでは
> ありません。詳細は `docs/maturity.md`。

## 0. 起動する

環境変数がひとつでも足りなければ**起動しません**。「とりあえず動く」既定値は
用意していません —— 給与の窓口が、誰も選んでいない設定で開くことがないように。

```bash
PAYROLL_STORE=ephemeral \
PAYROLL_ALLOWLIST='did:key:z6Mk…=emp-1' \
PAYROLL_AUTH=trusted-header \
PAYROLL_DID_HEADER=X-Verified-DID \
PAYROLL_PORT=8413 \
clojure -M -m payroll.host.jvm
```

| 変数 | 未設定なら | 何のためか |
|---|---|---|
| `PAYROLL_STORE` | 起動拒否 | `ephemeral`（消える）か `datomic`。誤字は黙って選ばない |
| `PAYROLL_ALLOWLIST` | 起動拒否 | `DID=事業主ID` の並び。**空＝全員拒否ではなく未設定** |
| `PAYROLL_AUTH` | 起動拒否 | `trusted-header` のみ。「認証なし」という値はありません |
| `PAYROLL_DID_HEADER` | 起動拒否 | 前段のプロキシが検証済み DID を入れるヘッダ名 |
| `PAYROLL_PORT` | 起動拒否 | `0` は OS 任せ（試験用） |
| `PAYROLL_BIND` | `127.0.0.1` | loopback 以外にするには `PAYROLL_TRUST_FORWARDED=yes` が別途必要 |

**`trusted-header` はヘッダそのものが認証です。** socket に到達できるものは
誰にでもなれるので、必ず検証をするリバースプロキシの背後の loopback に置いて
ください。`PAYROLL_BIND` を広げるときに `PAYROLL_TRUST_FORWARDED` を別の変数に
してあるのは、「コンテナの都合で bind を広げた」ときに、同時に安全性の根拠を
外したことに気づかない、という失敗を防ぐためです。

起動すると、保存先が再起動を越えるかどうかを標準出力に出します。
`GET /api/health` は同じことを常に答えます。

**現時点ではどちらの `PAYROLL_STORE` でも再起動を越えません。**
`ephemeral` はプロセス内の atom、`datomic` は protocol の差し替えは済んで
いますが既定の `:db-api` が in-process の DataScript です。

すべてキーボードだけで操作できます。JavaScript は 1 行も配信していません。

## 2. 記号の読み方

金額の隣の記号は、**その数字を誰が出したか**を表します。色だけで区別している
ものはひとつもありません（印と語が常に付きます）。

| 記号 | 語 | 意味 |
|---|---|---|
| ● | 確定 | 当 repository が登録事実と読んだ条文から計算した |
| ◆ | 申告値 | operator または proposal が申告した。**検算していない** |
| ◇ | 取込値 | 他システムのファイルから読んだ。列名も金額も未検証 |
| — | 該当なし | 登録事実により発生しない。**零ではない** |
| ? | 未確定 | 誰も出していない。**零でも空欄でもない** |
| ▲ | 保留 | この項目を理由に run が保留されている |

**「該当なし」と「未確定」は逆の指示です。** 前者は調べるものが無い、
後者は調べに行く必要がある、という意味です。

**総支給額と差引支給額以外は、ほぼ常に「申告値」になります。**
健康保険・介護保険・雇用保険の料率も、源泉所得税の月額表も、この repository は
読み終えています（下記 8 の表）。**それでも明細の所得税は「申告値」のままです。**
表を持っていることと、明細をその表から計算することは別の決定で、後者はまだして
いません —— 明細に出る所得税は、いまも operator が入れた額です。

厚生年金だけは条文に料率があるので、標準報酬月額から出る厳密値との差が
一円未満であることだけは検査します —— それは額を保証するものではなく、
**どんな端数処理でも届かない値を弾く**だけです。

## 3. 契約を登録する

`/console/employees` の「契約を登録する」から。

**「未登録（観測していない）」を選んだ項目は、未登録のまま保存されます。**
`false` で埋めることはしません。被保険者資格が未登録の run は保留され、
保留の理由がどのキーを登録すべきかを名指しします。

登録に要る観測値:

| 項目 | 未登録だとどうなるか |
|---|---|
| 健康保険・介護保険・厚生年金・雇用保険の被保険者資格 | その保険について run が保留される |
| 標準報酬月額（円）と対象月（YYYY-MM） | 社会保険の run が保留される。保険者等が決定する額で、当 actor は計算しません |
| 扶養控除等申告書の提出 | 年末調整の評価が保留される |
| 振込先（金融機関コード・支店コード・預金種目・口座番号・受取人名） | 振込データにその人が載らない |
| 受取人名は**半角カナ**で | 全角からの変換も、漢字からの読みの推定もしません。通帳の名義を見て登録してください |
| MoneyForward 従業員番号 | 突合の対象になりません。氏名での推測照合はしません |

**この登録層が知らないキーは拒否されます。** 打ち間違えたキーを黙って
受け入れると、登録したつもりの事実が登録されないまま画面だけ通ります。

## 4. 給与計算をする

`/console/run` から契約と期間を選び、控除額を入れます。

**所得税と四つの社会保険料は、この actor が計算するものではありません。**
operator が計上する額です。空欄は零ではなく「未回答」として扱われ、run は
保留されます。

**「控除合計」は下の五つの合計と一致させてください。** 一致しないと、
給与明細の差引支給額も仕訳も拒否されます —— 給与明細は食い違いを黙って
一方に寄せてよい書類ではないからです。

結果の画面は項目ごとに「金額・出所・理由」を出します。保留された項目は
金額欄そのものに理由が出ます（欄外の注記ではありません）。

### 月給契約の注意

**月給契約では勤怠は金額の計算に一切使われません。** 総支給額は契約月額
そのものです。画面はそれを毎回明示します（「勤怠を金額計算に使ったか: 未登録
／使っていない」）。

したがって、月の途中の入社・退社・欠勤・時間外労働がある月は、この金額は
**自信を持って間違います**。時間外労働時間などを勤怠に登録すると run は
保留され、保留の理由が「割増賃金の条文を読んでいない」と述べます。
黙って通ることはありません。

## 5. 書類を取り出す

`/console/exports` から。**どれも法定様式ではありません**（画面が列で
そう表示します）。

| 書類 | 形式 | 主な注意 |
|---|---|---|
| 給与支払明細書 | JSON / 印刷用 HTML | 交付義務・記載事項の法令が未読 |
| 賃金台帳 | CSV / JSON | 保留された run も行として入ります |
| 控除額集計 | CSV / JSON | ひとつでも未確定があれば合計は「未確定」になります |
| 振込データ | CSV / JSON | **全銀フォーマットではありません**（独自列） |
| 仕訳 | JSON | 勘定科目の対応表が未登録なので、現状はすべて拒否されます |

## 6. 住民税の決定通知書を登録する

`/console/operations`（運用の現況）の「決定通知書・変更通知書を登録する」から。

**この actor は住民税の額を計算しません。** 額を決めるのは区市町村で、
毎年5月末日までに「特別徴収税額の決定通知書」という紙が事業所に届きます。
ここでやるのは、その紙に印字されている数字を**そのまま書き写す**ことだけです。
所得税と違って、計算の手間はありません。

### 画面に入れる項目

手元の通知書を見ながら、上から順に埋めます。

| 欄 | 紙のどこを見るか | 入れないとどうなるか |
|---|---|---|
| 区市町村 | 通知書を出した区市町村の名前 | 登録できません。納入先はここで決まります。「/」は入れられません |
| 通知の種類 | 「決定通知書」か「変更通知書」か | **選ばないと拒否されます。**既定値はありません（黙って「決定通知書」にはしません） |
| 年度（YYYY） | 徴収が6月から始まる年度 | 登録できません |
| 指定番号 | 区市町村が事業所に付けた番号 | 任意です。空欄でかまいません |
| 通知書番号 | その紙に付いている番号 | 登録できません。あとで訂正が届いたとき、どの紙を差し替えるのかを名指しするために要ります。「/」は入れられません |
| 改訂番号 | 紙には書いてありません | **最初に登録する紙は `0`。**訂正・再交付を受け取ったら 1、その次は 2 と上げます |
| 差し替える通知の ID | 紙には書いてありません | 改訂番号が 0 のときは空欄。1 以上のときは必須（下記「訂正が届いたとき」） |
| 変更の適用開始月 | 変更通知書に書かれている「何月分から変わるか」 | 決定通知書のときは「指定しない」。変更通知書で選ばないと拒否されます |
| 年税額（円） | 通知書の年税額 | 決定通知書では必須。12か月の月割額の合計と一致しないと拒否されます。変更通知書は空欄でかまいません |
| 受領・転記した日 | 紙が届いた日、または書き写した日 | 登録できません。この actor は暦を持っていないので、日付は入れてもらう値です |
| 月割額（6月から翌年5月までの12か月） | 各月の欄の金額 | 決定通知書は12か月すべて。変更通知書は適用開始月から翌年5月までを入れます |

**空欄は「0円」ではありません。「まだ書き写していない」です。** 12か月のうち
11か月しか入っていない決定通知書は、11か月分として保存されるのではなく、
**登録そのものが拒否されます**。0円と入れて埋めるのもやめてください ——
それは区市町村が決めていない控除額を、決まったことにしてしまいます。

**年税額と月割額の合計が合わないときも拒否されます。** どちらも同じ一枚の紙に
印字されているので、合わないのは「安い税金」ではなく**書き写しの間違い**です。
桁を落とした月割額は、そのままなら一年間ずっと引かれ続けます。

### 登録できたとき

**画面が切り替わり、上に「通知を登録した」と出ます。** その下に、いま登録して
ある通知の一覧（区市町村・年度・種類・改訂番号・登録した月数・差し替えられたか）
と、年度ごとに「12か月のうち何か月ぶんの通知があるか」が出ます。

**画面にも住所欄（URL）にも、金額は一切出しません。** 月割額も年税額も出ません。
額はお手元の紙に印字されています。この画面は運用の状態を見るためのもので、
一枚の写真で誰かの税額が外に出てよい場所ではありません。

### 同じ通知をもう一度送ったとき

**「同じ通知が既に登録されていた」と出ます。エラーではありません。**
中身がまったく同じであれば、二度目は何も追記されません —— 送信ボタンを二度
押しても、通知が二つになることはありません。

同じ通知書番号・同じ改訂番号なのに**中身が違う**場合は拒否されます。
書き写しを直したいときは、次の「訂正が届いたとき」と同じ手順を踏みます
（改訂番号を上げて、差し替える通知を名指しする）。

### 訂正・再交付・変更通知が届いたとき

区市町村から「特別徴収税額の**変更**通知書」や、訂正された決定通知書、
再交付された通知が届いたら、**元の登録を書き換えるのではなく、新しく登録します。**

1. 元の通知が**まだ登録されていなければ、先にそれを登録します。**
   登録されていない紙を訂正することはできません。
2. 新しい紙の内容を、上の表のとおりに入れます。
3. **改訂番号を 1 つ上げます**（元が 0 なら 1）。
4. **「差し替える通知の ID」に、元の通知の ID をそのまま入れます。**
   ID は画面の一覧から見られます。改訂番号が 1 以上なのにここが空欄だと
   拒否されます —— 何を訂正したのか分からない訂正は、同じ年度について通知を
   二つ並べるだけで、どちらの額を引けばよいのか誰にも答えられなくなるからです。
5. 訂正の訂正をするときは、**直前の通知**（いちばん新しい紙）を名指しします。
   同じ通知を二つの通知が差し替えると拒否されます。

**元の通知は消えません。** 差し替えられた通知も一覧に残り、「差し替えられた
（記録として残してある）」と表示されます。従業員に「なぜ8月と9月で控除額が
違うのか」と聞かれたときに、両方の紙といつ書き写したかを示せるのは、
消していないからです。

### 間違えて登録してしまったとき

**登録した通知を消すことはできません。取り消しの操作もありません。**
できるのは、正しい内容の通知を**改訂番号を上げて登録し、間違えた通知を
差し替えること**だけです。そうすると、間違えた通知はその月を決めなくなり、
正しい通知の額が使われます。記録としては両方残ります。

消せないのは不便に見えますが、これは意図してそうしています。ここに入っている
のは実際に給与から差し引いて区市町村に納めた額の根拠で、**後から書き換えられる
記録は、何を差し引いたかの証拠になりません** —— 最後に誰がそう思っていたか、
の記録にしかなりません。

### 通知が無い月について

**この actor は税額を計算しないので、通知に無い月は「ゼロ」ではなく
「わからない」です。** 給与明細のその行は「未確定（?）」のままになります。

**住民税が「わからない」ままの run は、支払可になりません。** 振込データも
その run については作られません。これは出力の不具合ではなく、拒否です ——
額が分からない控除を、分からないまま引いて振り込むことはしません。

**未登録は「対象外」ではありません。** 所得税を源泉徴収する事業主は特別徴収
義務者に指定されるので、特別徴収の対象かどうかを誰も登録していない従業員は、
「対象外」ではなく「まだ調べていない」として扱われ、明細の行は「未確定」に
なります。

### 「特別徴収の対象かどうか」を登録する欄（2026-08-26 に付きました）

契約の登録画面（従業員・契約）に **「住民税の特別徴収」** という選択欄が
あります。選べるのは三つです。

| 選ぶもの | 明細の住民税の行がどうなるか |
| --- | --- |
| **未登録（分類していない）** | 「未確定（?）」のまま。通知書がその月を網羅していても額は出ません |
| **特別徴収（給与から差し引く）** | 通知書に書かれたその月の月割額が出ます。区市町村の名前が根拠として付きます |
| **普通徴収（本人が納付する）** | 「該当なし（—）」。**ゼロではありません** |

**最初の選択肢は「未登録」で、放っておいても「特別徴収」にはなりません。**
これは意図してそうしています —— 欄に触らなかったことを「この人は特別徴収の
対象だと誰かが判断した」と読み替えるわけにはいかないからです。手引きは
「切替理由書の提出がない場合、原則どおり、特別徴収対象者となります」と
書いていますが、それは**誰かが分類した結果としてそうなる**という意味で、
画面が黙って埋めてよいという意味ではありません。

未登録の従業員は、契約カードの「未登録の事実と、その結果」の表に出てきます。
そこに出ている間は、その人の住民税の行は保留されたままです。

**この actor が住民税の額を計算するようになったわけではありません。** 出るのは
通知書に書いてある月割額をそのまま引き写した数字で、その旨が行の根拠として
表示されます。

### この画面がしないこと

- **納入書は作りません。** 様式を読んでいません。納入書は区市町村から送られて
  きます。画面が出すのは、区市町村ごとの合計と「翌月10日」という期限の規則
  までです
- **納期限の日付は出しません。** 「10日が土日祝なら次の平日」は暦の規則で、
  この actor は暦を持っていません。「翌月10日」と、その規則の文言を並べて
  出すだけです
- **eLTAX にも、給与支払報告書の提出にも、つながっていません**
- **退職時の一括徴収も、異動届も、扱いません。** 手引きから読み取った事実
  としては書いてありますが、画面も書類もありません
- **通知が本物かどうかは確かめません。** 登録されているのは、操作者が紙を
  書き写したものです

## 7. MoneyForward と突合する

`/console/mf` にエクスポートの中身を貼り付けます。**ファイルは保存されず、
取り込んだ金額が run になることもありません。** 突合だけをします。

> **実際の MoneyForward のエクスポートを、この repository は一度も読んで
> いません。** 画面に出る列名はすべて推測で、名前が違えばその列は読み込まれ
> ません。読み込まれなかった列は「この repository が知らない列」として
> 報告され、突合は成立しません。

判定は 5 値です。**「一致」以外はすべて未解決**として扱ってください。

| 判定 | 意味 |
|---|---|
| 一致 | 両方に数字があり、等しい |
| 不一致 | 両方に数字があり、違う |
| MF のみ | MoneyForward にだけ数字がある |
| 当 actor のみ | こちらにだけ数字がある |
| 比較不能 | こちらが保留していて、比べる数字が無い |

**「比較不能」は一致ではありません。** 当 actor が何も計算していない月を
「差分なし」と読むのが、この画面がいちばん避けたい誤りです。

突合が成立する（`reconciled?`）には 6 つ全部が要ります: 取り込みが拒否されて
いない／**1 件以上の run を比較できた**／全 run 全項目が一致／紐づかない行が
無い／知らない列に値が無い／**対応する概念が無い控除に値が無い**。

**住民税は突合の対象になりました。** 以前はこの actor に対応する項目が無く、
エクスポートに住民税の値が入っているだけで突合が成立しませんでした。いまは
住民税の列も他の控除と同じように項目ごとに比べられ、「対応する概念が無い控除」
に当たる列は一つもありません。

ただし**この actor が住民税を計算するようになったわけではありません**（上記 6）。
決定通知書を登録していない月は、こちら側の額が「未確定」なので判定は
**「比較不能」**になります。**「比較不能」は一致ではありません。**
普通徴収として登録してある従業員の月は、こちら側が「該当なし」なので
**「MF のみ」**になります。どちらも、黙って一致として数えられることはありません。

## 8. MoneyForward をやめるまで — 3 サイクルの手順

`GET /api/operations` が、いま何が足りないかを毎回答えます。同じ内容は
「運用の現況」の画面（`/console/operations`）でも読めます —— 組み立てているのは
1 箇所だけなので、答えは同じものです。以下はその条件を満たすための**操作の順序**
です。

### 毎サイクル（給与 1 回分）、3 回くり返します

1. **こちらで給与計算をして確定する**（上記 4）。当 actor が何も計算して
   いない月は突合が「比較不能」になり、**「比較不能」は一致ではありません**。
2. **MoneyForward のエクスポートを `/console/mf` に貼る**（上記 7）。
   ファイルは保存されません。照合は**登録された従業員番号**でのみ行い、
   氏名では行いません。
3. **そのサイクルを証拠として保存する。** 突合レポート・承認者・承認時刻・
   両側の識別子（kotobase の node CID）・月の種別を一緒に記録します。
   **「突合できた」は、レポートから複写される値であって、入力する値では
   ありません。** 比較した run が 0 件のレポートからはサイクルを作れません。
4. **月の種別に理由をつける。** 「通常の月」か「通常でない月」か。
   **3 回のうち少なくとも 1 回は「通常でない月」**（中途入社・中途退職・
   欠勤・無給休職・割増賃金の発生など）でなければなりません。理由の無い
   「通常でない月」は拒否されます。

   > 月給契約の総支給額は契約月額そのもので、勤怠を読んでいません。
   > 通常の月なら正しく、通常でない月でこそ二つの system は食い違います。
   > **通常の月が 2 回一致しても、3 回目については何も証明しません。**

5. **分析用の投影（R2）に書き、読み戻して確認する。** 書き込みが成功したと
   いう応答ではなく、**書いたものが実際に返ってくること**を確認します。
   何も保存しなかった保存先に対する成功応答は、成功と見分けがつきません。

### 満たすべき 6 条件

| # | 条件 | いま |
|---|---|---|
| 1 | **連続する 3 サイクル**が突合済み | 0/3。間に突合できない月があると連続は途切れ、数え直しになります |
| 2 | うち 1 つ以上が「通常でない月」（理由つき） | 未 |
| 3 | 知らない列・対応概念の無い控除に値が無い | 未。住民税はもう「対応概念の無い控除」ではありません |
| 4 | 証拠が **kotobase** に在る（再起動を越える保存先） | 未。transport が未設定です |
| 5 | その kotobase から**欠落なく読み戻せた** | 未 |
| 6 | **R2 の投影**から読み戻せた | 未。token の権限が不足しています（下記） |

4 と 5 が別の条件なのは、プロセス内の保存先が 5 だけなら簡単に通るからです
——完璧に読み戻せて、プロセスが終わるまでは。切り替えの証拠がプロセスの中に
しか無い状態は、最初の再起動でそれが無かったことになります。

**この 6 条件に「担当者が確認した」という項目はありません。** すべて機械が
測っており、`true` にする引数はありません。

### 6 の権限について（担当者へ渡す言葉）

R2 Data Catalog に対して `create_namespace` は通り、`create_table` が **401**
を返します。token に必要なのは**二つ**です:

- **R2 Data Catalog** の読み書き権限（admin-read-write）。上の 2 つは
  どちらも書き込みです
- `R2_WAREHOUSE` が指すバケットに対する **R2 ストレージ**の読み書き権限。
  Iceberg のテーブルメタデータはそのバケットの中のオブジェクトです

catalog だけに絞った token は、まさに上の症状になります。「token が違う」の
ではなく「権限が一つ足りない」です。

### この手順の外に残るもの

- 銀行が実際に受け取るファイル形式（試験振込で確認）
- 住民税の**納入書**（様式が未読）、**eLTAX** への提出、退職時の**一括徴収**、
  **異動届** —— どれもこの system にはありません。決定通知書の登録・明細の行・
  突合までは揃っています（上記 6）
- **年末調整の年税額はこの system では出せません。** 月額表は転記済みですが、
  年税額に要るのは別表第五と所得税額の速算表で、どちらも読んでいません。
  年間の給与を月額表に通せば数字は出ますが、それは年税額ではありません
- 法定調書は下書きの形までで、税務署に出せる様式ではありません

## 9. 困ったとき

- **run が保留された** → 画面の「保留の理由」に規則名と説明が出ます。
  多くは「登録が要る: `:employment/…`」という形で、登録すべきキーを名指し
  します
- **金額が「未確定」のまま** → その行の理由欄が、誰が出すべき数字かを述べます
- **突合が成立しない** → 画面上部の理由が、6 条件のどれが満たされていないかを
  述べます
- **起動しない** → 標準エラーに、どの環境変数が足りないかと、その理由が出ます
- **再起動したら記録が消えた** → 仕様です。`GET /api/health` が起動時から
  そう答えています
- **切り替えの進捗が 2/3 から 1/3 に戻った** → 仕様です。間に突合できない月が
  あると連続が途切れ、そこから数え直します。表示は「これまでに何回よかったか」
  ではなく「いま何回連続しているか」です
- **源泉徴収税額が「端数処理が未転記」で拒否された** → 740,000円超（甲）と
  105,000円未満（乙）は、税額表が金額ではなく**率**を印字している区間です。
  率が生む 1 円未満をどう処理するかは印字されていないので、厳密な値だけを
  返して丸めは拒否します。この区間だけは、額を人が決めて登録してください
